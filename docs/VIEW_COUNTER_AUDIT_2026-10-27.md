## Почему значения различаются

Сумма накопленных интервальных приращений за несколько дней не равна сумме текущих счётчиков активных объявлений. Текущая выборка может отличаться от исторической. Интерфейс восстанавливает архивы, поэтому число снимков больше двух.

## Риск корректности

В архиве обнаружены одиночные скачки просмотров свыше 30 000 между соседними обходами, например объявление 4160590 (+33 351) и 4176730 (+33 344). Это полученные из сохранённых данных разности, но **не доказанное количество реальных заинтересованных покупателей**. Причина скачков не подтверждена; без проверки источника нельзя приписывать их органике или рекламе.

## Правило интерфейса

Нельзя автоматически удалять или обрезать исходные данные. Показывать наблюдаемые разности с ясным предупреждением, что необычные скачки не проверены. Нельзя выдавать результаты за звонки, открытия телефона, уникальных покупателей или чистый органический трафик.

Внесённые изменения ограничены тестовой веткой; сборщики и историю не меняли.

## Дополнительная сверка 27 октября, 13:00 по Минску

По конкретному UUID в сохранённых снимках счётчик менялся как 327 → 32 793 → 187, а затем возвращался к значениям около 300. Сохранённая отдельная история API для этого объекта содержит значения порядка 0–242 на датах до начала наблюдения. Это подтверждает противоречивость данных, но не определяет однозначно, где возникла ошибка: в сопоставлении значений UUID, ответах API либо преобразовании источника.

В `collector.py` функция `fetch_views` сопоставляет входящие UUID со списком ответов по позиции: `zip(batch, arr)`. Запрос `objectsViewsCountsByUuids` запрашивает только `views`, а идентификаторы объектов в ответе не используются. Если размер или порядок ответа отличается от входного списка, значения могут быть приписаны чужим UUID. Это проверяемая гипотеза, а не установленная причина.

Для безопасного просмотра в тестовой версии `periodData` исключает из рейтингов объявления со снижавшимся счётчиком внутри периода; исходный архив сохраняется. Для возвращения полной достоверной аналитики требуется отдельно проверить и, возможно, изменить механизм привязки просмотров к UUID в сборщике. Это не было выполнено.
